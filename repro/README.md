# Reproduction: "Weak Diffusion Priors Can Still Achieve Strong Inverse-Problem Performance"

Paper: Jia, Yuan, Liu, Shen, Wang. ICML 2026 (spotlight), arXiv 2601.22443v2.

**Rule followed:** everything is implemented from the paper text and its appendix. The authors' code repository and project page were never opened. Baseline details come from the cited papers:
- DPS: Chung et al., ICLR 2023, Alg. 1 and App. D.
- DMPlug: Wang et al., NeurIPS 2024, App. D.2.

Results tables are generated by `summarize.py` into `../results/summary.md`.

## How to run (conda env `weakprior`)

```bash
P="python -s"                   # python of the weakprior env (setup: ../README.md)
$P repro/prepare_data.py        # 100 test images per domain -> data/test/{celeba,bedroom,church}
git clone https://github.com/VinAIResearch/blur-kernel-space-exploring data/bkse   # nonlinear deblur; put GOPRO_wVAE.pth (link in its README) in data/bkse/experiments/pretrained/
$P repro/selftest.py            # operators, holdout split, AdamSphere geometry, fp16 gradient check
$P repro/exp_toy.py             # Figure 2 + numerical check of Theorem 3.2       -> results/toy
$P repro/exp_autocorr.py        # Tables 2 and 14                                   -> results/autocorr
$P repro/exp_scoregap.py        # Table 1                                           -> results/scoregap
nohup bash repro/queue.sh > logs/queue.log 2>&1 &   # Tables 3-7, 12, 16 (resumable; stop: touch logs/STOP)
$P repro/summarize.py           # -> results/summary.md
```

Single cells can also be run directly, e.g.:

```bash
$P repro/run.py ino --task inpaint --target celeba --prior bedroom --n 5
```

### On Arrhenius (NAISS, GH200 GPUs, account `naiss2026-4-1816-gpu`)

The main results (100 images per cell) were run there.
- The code and `data/test` live in `~/weakprior_repro`.
- The venv is a single tar file in `/nobackup/proj/disk/naiss2026-4-1816/personal/wenxuanl/weakprior_repro/env.tar`, unpacked to node-local scratch by every job, because the project disk's file-count quota is almost full.
- See `cluster/env.sh` for why the native aarch64 Python is used instead of modules.

```bash
rsync -a --exclude __pycache__ repro arrhenius:weakprior_repro/ && rsync -a data/test arrhenius:weakprior_repro/data/
ssh arrhenius 'cd weakprior_repro && sbatch repro/cluster/setup.sbatch'          # once: venv, model caches, selftest
ssh arrhenius 'cd weakprior_repro && sbatch --array=1-67 repro/cluster/cells.sbatch 100 25 &&
               sbatch --array=68-76 -t 05:00:00 repro/cluster/cells.sbatch 100 1'   # 76 cells of cluster/cells.txt
rsync -a arrhenius:weakprior_repro/results/runs/ results/runs/                    # then summarize.py / make_figures.py
```

`--batch B` optimises B images per pass. Every image keeps its own seed, loss, Adam state and selection rules, so B changes only speed and floating-point details.
- Measured on a GH200: INO 21 s/image (B = 16), DPS 10 s/image, DMPlug 60 s/image (always B = 1).
- The laptop runs for the first 2 images of 9 cells are kept in `results/runs_a1000`, as a check that results do not depend on hardware.

## Implementation choices (paper statement → what we do)

| item | paper | here |
|---|---|---|
| priors | `google/ddpm-{celebahq,bedroom,church}-256` (App. C.12) | same checkpoints |
| weak generator | "3-step DDIM" | Deterministic DDIM (η = 0), clip x̂0 to [-1, 1]. Timesteps **[666, 333, 0]** (diffusers "leading" default). The paper does not state the spacing; Table 2 identifies it: leading matches its 3-step autocorrelations (RMSE 0.035 / 0.015), trailing [999, 666, 333] does not (0.099 / 0.084). |
| objective | Eq. (2), MSE on observed entries | sum of squared residuals on the fit entries; Adam is invariant to the scale |
| AdamSphere | App. B | Project the gradient to the tangent space, apply Adam moments (β = 0.9 / 0.999, ε = 1e-8), project the direction to the tangent space, step, normalisation retraction to r = ‖z₀‖. |
| learning rate / holdout split | Table 19: inpaint 0.02 / 10 %, Gaussian 0.02 / 20 %, SR 0.01 / 5 % | Same. Box inpainting uses the inpainting setting; 16× SR uses the SR setting. |
| HoldoutTopK K | not given ("K > 1") | **K = 5**, fixed before any result. K ∈ {1, 3, 10, 20, 50} reported as sensitivity. Selection runs over the full 1000-iteration trajectory. |
| iterations | 1000 (App. C.12) | 1000 |
| random inpainting | 70 % of pixels removed | exactly 70 % of pixel positions; mask shared by RGB (as in DMPlug App. C.2) |
| SR | "downsampling ×4"; Sec. 3.2: average over non-overlapping blocks | 4×4 (16×16) block average |
| Gaussian deblur | kernel 61, intensity 3 | 61×61 Gaussian, std 3, reflect padding |
| box inpainting | "contiguous square region" | centred square of side 0.3 to 0.6 × 256 |
| nonlinear deblur | "BKSE (GOPRO wVAE.pth)", lr 0.01, holdout 10 % (Tables 18, 19) | y = F(x, k) + n with BKSE's `KernelWizard.adaptKernel` on [0, 1] images, no clamping, full fp32 (with TF32 a GH200 gives a different y on each call, up to 1.3e-3). One kernel code k ~ N(0, 1.2² I) of shape 512×2×2 per image: the 1.2 is from BKSE's `generate_blur.py`, DPS Eq. 58 leaves σ_k open. BKSE code (commit f2fe73e) and weights go in `../data/bkse`. |
| noise | σ = 0.01 on [-1, 1] images | same; for inpainting, noise only on observed pixels |
| DPS | 1000-step DDPM, "default config" | DPS Alg. 1 with ζ_i = ζ′/‖y − A(x̂0)‖, ζ′ = 1 (DPS App. D, all FFHQ linear tasks). Implemented as x ← x′ − ζ′∇‖y − A(x̂0)‖. x̂0 clipped; fixed_small variance. |
| DMPlug | "default config" | Adam lr 1e-2, 3-step DDIM, fit on all observed entries, ES-WMV with window 10, patience 100 (DMPlug App. D.2), 1000 iterations max |
| ablation (A) / (C) "variance" ES | Table 5 | ES-WMV evaluated on the same trajectories as (B) / (D); those fit 90 % of the observed entries |
| test images | "100 random test images" | 100 random images (seed 0) from CelebA-HQ-256 val (2000) and the official LSUN bedroom / church_outdoor val sets (300 each); a guided-diffusion crop is used for LSUN |
| metrics | PSNR, SSIM, LPIPS | PSNR on [0, 1]; SSIM with an 11×11 Gaussian window (σ = 1.5); LPIPS VGG and AlexNet (both stored) |
| precision | not stated (L40S GPUs) | fp16 UNet weights + `torch.compile`. ε-prediction relative error ≈ 4e-4 (same as PyTorch's default TF32). INO gradient cosine vs fp32 = 0.99998. |

## Scale reduction (hardware)

The paper used 8× L40S and 100 images per cell. Here, every cell uses the same 100 images, run on NAISS Arrhenius GH200 GPUs.
- Cost: about 55 GPU-hours for all 82 cells (76, plus 6 for nonlinear deblurring).
- The laptop RTX A1000 (8 GB; INO ≈ 6 min/image, DPS ≈ 2.5 min/image) would have managed only 5 images per cell in 36 h.
- Results are reported as mean ± standard error. Every method sees the same images, masks, noise and z₀.
